# 路线图与功能边界

## 当前实现

个人自托管 React PWA + Fastify + MySQL；固定账号登录、用户数据隔离、月/周预算与日结转、单日预算、支出与退款、统计、固定支出预留、备份及解压后的微信/支付宝 CSV 导入。

收单支持明确支付/退款文本、常见通知对象、结构化交易、秒级时间与稳定事件 ID。日期/时间优先显式参数和原文，缺失时保存接口接收时刻；接收时间不等同于支付时间。原历史数据、邮件、CSV 或手工记录仍可保留未知时间。

已覆盖匿名银行「账户出账 网联支出」「发生快捷支付扣款」等模板，并扩充收入/支出/退款近义词：普通进账按退款入账，失败及处理中状态仍拒绝。手机提交正文字符串完成收单已有匿名验证结论；公开记录不包含真实金额、调用时刻、地址或设备标识。具体自动检查见 [PROGRESS](PROGRESS.md)。

可选 IMAP 轮询、Message-ID 收据事务防重、原文审计与 dry 诊断已有代码，需配置自己的邮箱并校准银行真实模板。当前不保证所有银行卡消费都有通知或邮件。

## 手机接入矩阵

| 通道 | 行为 | 仍需验证 |
|---|---|---|
| 操作按钮 OCR | 付款/退款详情截屏 → 文字 → POST | 权限、真实详情金额与时间 |
| 分享历史截图 | 相册单张图分享 → OCR → POST | 原日期、长期延迟/跨年与无时间内容 |
| 系统支持的通知自动化 | App/内容筛选 → 正文文字或通知对象 → POST | 原文属性、锁屏、延迟、重复与每种来源退款 |
| 短信/邮件个人自动化 | 发件人/关键词触发，有原文时 POST | 设备实际提供的输入与银行文案 |
| Wallet Transaction | 选定卡 tap 时触发 | 最终金额/状态，退款与扫码支付没有保证 |
| 服务器 IMAP | 异步轮询银行邮件 | 分笔提醒可用性、真模板、发件真实性 |
| 月度 CSV | 解压后预览并导入 | 部分退款与跨来源重复 |

Apple 的 [iOS 27 事件触发器指南](https://support.apple.com/guide/shortcuts/apd932ff833f/10.0/ios/27) 已列出通知和截屏触发器。能力随系统版本和实际输入变化，触发存在不表示支付平台每笔都发完整通知。逐动作配置见 [快捷指令指南](guides/shortcut-ocr.md)，手机登录与主屏幕入口见 [手机运行指南](guides/local-preview.md)。

- Web Push/服务器定时提醒；当前固定支出只在打开首页时展示。
- Cloudflare Worker 中转；现有目录只有设计说明。

- Docker/Caddy 云部署端到端验收；本机成功不代替公网验证。
- 如需多人使用，独立收单归属、开放注册和共享账本设计。

## 已知边界

- 服务器或网络不可达时不能新增交易，当前没有自动补发保证。
- 不能从旧记录恢复真实秒数，分钟输入只作格式补零。
- 未明确成功、未完成的进账/支出或金额歧义返回未匹配，需手工核对；结构化接口由调用方先确认交易。
- 缺来源时间时接收秒数不参与去重，重试保留首次记录；跨午夜使用稳定事件 ID。
- 缺事件 ID、真实时间和其他区别信息时，同额多笔仍可能无法区分。
- 邮件、OCR、CSV、手工记录不保证完全自动对账。
- 自动测试只验证已覆盖模板；每种平台/系统的实际行为须分别留匿名证据。
