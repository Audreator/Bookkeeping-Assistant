# 当前架构

## 总览

```text
iPhone Safari / 主屏幕 PWA
        │ HTTP(S) /api（登录 JWT）
        ▼
Fastify 服务器（server/，端口 8787）
        │ Drizzle ORM / mysql2
        ▼
MySQL 8（本地 Docker，127.0.0.1:3306）
        ▲
        │ 收单路由 / 可选 IMAP 轮询
个人快捷指令（独立 INGEST_TOKEN）/ 银行邮件
```

- 生产模式 `npm run start` 提供 `dist/` 与 API；开发模式 `npm run dev:all` 启动 Vite 5173 和 API 8787，Vite 代理 `/api`。
- React SPA 用 HashRouter；数据通过 API 存入 MySQL，当前没有 Dexie 数据库与离线交易队列。
- 统计页按需加载；应用错误边界对渲染或页面资源加载失败给出中文刷新提示，不自动反复刷新，也不清除登录和账本数据。旧入口需先刷新到新构建才获得这项保护。
- 固定单用户登录，生产注册关闭；业务表仍按 `user_id` 隔离。新增设备登录会使原会话失效。
- 公开源码不预填个人账号；固定账号来自本机 `.env`，示例用户名为 `owner`。真实密码、JWT/收单令牌和数据库连接不进入前端构建，运行期配置与发布源码分别保存。

## 目录职责

底部 `TabBar` 使用 `NavLink` 保留当前页 `aria-current`；悬浮玻璃胶囊中的五项入口各自保留触控范围、键盘焦点与蓝色选中提示。菜单、记账悬浮按钮及页面留白共同考虑 `safe-area-inset-bottom`，编辑弹窗层级在菜单之上。

| 路径 | 职责 |
|---|---|
| `src/engine/` | 预算引擎纯函数与 TDD 测试 |
| `src/lib/` | 日期、统计、备份、CSV 解析与纯逻辑测试 |
| `src/api/` | fetch 封装、类型、TanStack Query hooks |
| `src/state/` | 登录态与引擎输入组装 |
| `src/pages/` | 今天、账本、规划、统计、设置与登录 |
| `src/components/` | 交易、记账弹窗、日历、导航、备份导入等 |
| `server/src/routes/` | JWT 业务 API 与独立令牌收单 API |
| `server/src/ingest/` | 支付文本解析及测试 |
| `server/src/email/` | 邮件解析、收据审计、可选 IMAP 轮询 |
| `server/src/db/` | Drizzle schema、连接与迁移辅助 |
| `server/drizzle/` | SQL 迁移及 schema 快照 |
| `workers/relay/` | 中转设计占位，尚无部署代码 |
| `docs/superpowers/` | 原始 spec/计划历史，不是当前完成清单 |

前端通过 `src/api/hooks.ts` / `client.ts` 访问数据。当前服务器路由直接使用 Drizzle；尚未抽出 server repo。不要依赖历史文档中不存在的 `src/db/repo.ts` 或 Dexie 表。

`src/lib/apiBase.ts` 统一解析 API 前缀：非空构建变量 `VITE_API_BASE` 优先，否则以 Vite `BASE_URL` 和当前页面 URL 解析部署目录，去掉末尾斜线再拼接 `/api/...`。当前 Vite `base: './'`，根入口请求 `/api`，HashRouter 子目录入口请求该目录下的 `/api`；hash、query 和显式 `index.html` 不进入前缀。显式 `/` 可指定根 API，空配置继续自动推导。反向代理需将无斜线目录入口重定向到带斜线入口，并剥离目录前缀后转发。通用构建不再依赖部署时注入私有路径；此逻辑不改变 JWT、密码预哈希、会话续期或收单鉴权。

## 按钮与弹窗

`ModalToolbar` 统一弹窗顶部的圆形「×」与「✓」，分别调用关闭和保存回调；确认按钮在忙碌或不可用时显示灰色并禁用。底部文字按钮保留，和顶部确认按钮共享保存逻辑与忙碌状态。`Modal` 继续负责焦点约束、Esc 关闭和背景滚动锁定，关闭是否可用由调用方控制。

`src/index.css` 的显式 `ios-button` 类提供玻璃圆形、胶囊、蓝色主操作和红色危险操作，主要触控区域至少 44px，并支持键盘焦点、按下、禁用及减少动画/透明度偏好。日历日期、交易整行、分段选择控件使用各自样式，不全局套用胶囊外观；分类 emoji 和图表颜色保留。此层只改变交互呈现，不修改数据访问或收单合约。

底部导航的共享选择框位于链接下方，不接收点击或焦点：外层百分比位移通过 620ms CSS transition 连续滑动，内层 Web Animations 使用相同时长、分段缓动完成方向性滞后、前冲、单次制动与恢复。方向取未形变的 `.tab-selection` 当前包围盒到目标位置的有符号剩余位移，目标位置由 `.tab-track` 包围盒与当前入口计算；剩余距离按入口宽度换算，限制为 1～4 格后决定力度。无有效布局尺寸时才回退路由索引差，避免快速重定向尚未抵达前一目标时方向相反。横向峰值 1.64～1.70 倍，纵向 1.16 倍，起步反向偏移 3.5px，前冲沿移动方向偏移 6～7.8px，制动时反向偏移 2px 并回缩到 `scale(.94, 1.08)`，最终恢复。保持中心原点，不使用倾斜，确保折射镜像的轴向配准。

首次显示和重复点击当前页不回弹；连续切换先读取当前形态再取消旧动画，外层从当前插值位置续滑。动态监听 `prefers-reduced-motion`，启用时取消形变、直接定位；不支持 Web Animations 时保留 CSS 滑动，用可取消的 620ms 定时器覆盖透明移动态。减少动态效果或卸载都会取消动画与定时器、清除移动标识，并清理监听。50px 高入口加外框约 62px；形变可伸出外框，菜单和实际点击范围保持不动。页面背景为纯浅灰，稳定滚动条槽避免不同页面的滚动条使菜单横向跳动。

菜单使用 `backdrop-filter: none`，`::after` 叠加 `rgb(132 138 148 / 12%)` 淡灰雾，中心仍能看清原文字和图案。选择框仅停稳后使用 `#ffffff30` 白色背景（约 19% 不透明度）、`blur(14px) saturate(1.35)`，覆盖整个胶囊至边缘；停稳时不叠加选择框自己的灰雾，并隐藏其清晰折射镜像，防止 12px 边缘带覆盖毛玻璃，细亮轮廓保留。移动和回弹的整个 620ms 内，`data-moving` 状态清除选择框白色背景与模糊、恢复其折射带并叠加同样的 12% 灰雾。结束或取消回调校验当前动画身份与运动代次，避免快速重定向时旧回调提前恢复毛玻璃。菜单折射始终显示，选择框折射仅在移动和回弹时显示。导航轨道的层级在灰雾之上，图标与文字保持清晰和可交互。

灰雾统一从 `.glass-tabbar` 的 `--tab-glass-tint` 继承；菜单与移动选择框的 `::after` 外扩 1px，覆盖保留的透明边框区域。移除菜单／移动选择框的白色描边、内阴影和渐变高光，避免边缘材质比中心更白；仅停稳毛玻璃选择框保留自己的细亮轮廓。边缘局部形变与下方原内容仍可造成自然的明暗变化，不把同材质色等同于每个像素颜色相同。

`GlassRefraction` 复制 `main.app-page` 的当前 DOM 到非交互装饰层，在未形变的子层 `.glass-refraction-clip` 中按圆角形状裁切源与背景，再由父层的元素 `filter: url()` 和 `feDisplacementMap` 对已裁切输入作位移，最后仅显示边缘遮罩；不能只在滤镜输出端遮罩，否则源范围外的内容仍可能被带入。菜单与选择框的边缘带均为 12px，力度参数分别为 1.45、1.6；这些参数不是最终屏幕像素位移。边缘内容在同一局部带中拉长、压短，中心不形变。镜像使用 `aria-hidden`、`inert`、`pointer-events: none`，移除弹窗、脚本与事件属性，清空密码、文件和名称标识为令牌等敏感输入的值，并重映射 ID 和 SVG 引用，避免重复焦点、读屏和图表定义冲突。不会再次挂载业务组件或发出第二轮 API 请求。

纯逻辑 `src/lib/glassOptics.ts` 用圆角矩形有符号距离与双正弦边缘剖面生成位移图：边缘带宽 `L` 限制为不超过半宽、半高，力度 `A` 限制为不超过 `.85L / (2π)`；深度采样映射为 `F(d) = d + A sin(2πd/L) sin(πd/L)`，两端固定、单调有界，用局部压缩和拉伸代替整体偏移。返回的地图 `scale` 使用限制后的力度，SVG 不再使用未限制参数，避免极端尺寸下突破边界。Canvas 仅编码位移 PNG，不截图或上传页面。按 CSS 像素生成 1× 地图，只有尺寸/圆角/参数变化才重建，移动时仅校正镜像位置与缩放。版本化 filter ID 用于刷新 Safari 滤镜缓存；滚动、尺寸和页面变化按需同步，切换动画最多连续跟踪 700ms，静止时无持续帧循环。副本挂载并设定真实宽高后同步源内部的滚动偏移；后续子容器滚动按节点映射加入稀疏队列，不重新复制整页或生成地图，镜像滚动不触发反馈。卸载会断开观察器、移除事件监听、取消待执行帧并清空镜像。

当前实现无新增运行时依赖；Safari 的元素滤镜、1× 地图和缓存更新策略参考 [samasante/liquid-glass 的浏览器说明](https://github.com/samasante/liquid-glass/blob/main/BROWSERS.md)。开源实现可在遵守许可的前提下直接复用，具体片段及依赖按浏览器兼容性与功能需求选择，并保留版权／许可和来源。不支持边缘遮罩时仍显示从中心到外沿的统一灰雾，不支持背景模糊或启用减少透明度时停稳后的选择框使用 `#eeeeeef2` 浅色背景；减少透明度同时关闭选择框模糊，并使卡片、弹窗和按钮更实。移动态样式优先保持无模糊的淡灰雾，菜单始终保持通透淡灰雾。兼容实现不等于已完成 iPhone 真机验证，验证状态与核对步骤见 [玻璃界面指南](guides/glass-ui.md)。

应用图标由 `public/logo.svg` 的 `app-mark` 分组统一生成：Apple与普通PWA使用1.36倍主体，maskable独立渲染原始比例以保留安全圆。图标不预裁切外框，PNG全画布不透明；生成脚本同步各尺寸与favicon，Apple链接版本用于更新缓存。详见[图标维护](guides/icon-design.md)。

## 预算数据流

1. `useBudgetState` 从 API 拉取交易、预算事件、设置、固定支出与单日预算配置。
2. `computeBudgetState` 按日模拟发放、支出/退款与结转，今日可花 = 昨日结转池 + 今日基础日额 − 今日已花。
3. 调整预算按剩余预算重新分配；模式切换从当日新开期间，结转池按实际规则传递。
4. 单独设预算的当天用设定额减当日已花，其他天重新均摊；可修改/取消，无法均摊时提示总预算不足。
5. `computeReserve` 计算本期固定净付款 + 本期到期账单未覆盖计划余额；真实支付通过 `bill_allocations` 按金额关联固定用途，一笔可多项、同项可分次付款。`useBudgetState` 两遍计算：先确定当期边界，再仅把当期已确认且截至今天的固定分摊部分从日常交易金额中排除，带 `fixedReserve` 重算每日额度。历史期间仍保留原现金流水用于结转；跨期预付不重复预留，固定退款可使预留为负。预留关闭则使用原流水全額计算。统计和账本始终使用原始金额；首页标明日常预算，固定账单在设置管理。
6. 秒级交易时间用于记录展示与收单去重，预算按 `occurredAt` 日期汇总。

首页通过纯展示函数 `computeBudgetProgress` 解释有符号的日常净现金流：净支出为正显示使用金额与比例，净额为负显示正数净入账和 0% 使用比例。预算不为正时显示「暂无额度」，正常超支比例仍可超过 100%。引擎的 `spentInPeriod`、每日 `spent` 和剩余额度保持现金守恒，不因展示下限改写；固定分摊依然只抵扣一次。统计继续展示原始流水口径。

## 交易与收单数据流

- 普通交易 API：JWT 鉴权 → 用户过滤/归属校验 → 数据库 → 序列化返回。
- 文本收单：独立令牌 → 参数校验 → 最终状态/金额解析 → 显式或文本日期/时间 → 唯一键去重 → 入账。
- 退款金额标签只参与字段优先级，不证明完成。已全额退款／已返还等明确完成证据保留；银行快捷退款的省略状态模板要求个人账户末四位、可选日期时间、可选封闭 `【…】` / `[…]` 通道栏、可选「发生」及紧邻退款金额。通道栏最多 120 字且不允许嵌套或未闭合括号，支持其内部 OCR 换行；退款后的逗号和金额换行可兼容。完整尾部只允许结束、明确余额或查看详情提示，未知后文拒绝。括号摘要不作为显式商家；消息分钟补 `:00`，不虚构秒精度。
- 退款或进账证据优先于支付证据；支付／付款／付费／消费／扣款／扣费／支出／花费／支取／取现／转出／缴费／还款与退款／退费／退回／退还／退货／退单／返款／返还／冲正／撤销组成复合事件时，没有可信退款或进账完成依据便拒收（OCR 返回 `422`），不会截取「发生快捷支付退款」中的「支付」记为支出。申请、需确认与退款政策不自动记为已到账；独立「申请退款」按钮不影响明确付款成功页的识别。
- 结构化收单：独立令牌 → 类型、正金额、日期/时间校验 → 唯一键去重 → 入账。调用方负责先确认支付或退款成功。
- 固定用途分摊：`PUT /api/transactions/:id/fixed-allocations` 事务内完整替换关联；锁用户行统一串行分摊及受影响的交易/账单修改，校验归属、分精度、交易合计与固定退款覆盖。原流水不拆分、不伪造商户；有分摊的账单禁止硬删除，可停用。
- 旧固定支付入口：`POST /api/bills/:id/pay` 同一事务创建真实支出、支付标记与分摊；旧 `/api/bill-payments` 的交易关联也经同样校验，避免绕过限制。无准确金额的历史支付标记只作展示。新备份包含分摊，恢复先映射所有账单/交易 ID，再恢复付款、退款分摊。
- IMAP：邮件扫描 → 完整邮箱/域名边界过滤 → 复用严格支付解析 → 数据库事务中的 Message-ID 收据与交易。此通道需真实样本校准，地址过滤并非签名验证，不能等同于跨来源自动对账。

解析器更新只影响后续请求，不迁移历史分类。旧误分类需按核实后的交易 ID 通过普通 JWT 交易编辑接口修正；收单重放不会覆盖原记录：相同 `eventId` 类型冲突返回 `409`，内容去重键包含类型，没有稳定 ID 时重放可能新增退款而保留错误支出。有固定分摊的流水变更类型前，仍须通过现有分摊校验并撤销关联。

## 关键约定

- 金额：DB `DECIMAL(12,2)`，JS 展示/输出经 `round2()`。收单金额最多两位小数。
- `transactions.occurredAt` / `occurred_at` 是本地 `YYYY-MM-DD` 日期；`occurredTime` / `occurred_time` 为可空 `HH:mm:ss`。OCR/实时通知按用户规则优先消息时间、缺省接收时间；接收时间不进入去重指纹。旧记录、邮件、CSV 等未知来源时间保持空。
- `ingestKey` / `ingest_key` 为收单唯一键；稳定 `eventId` 支持并发重试。缺少来源交易号或真实时间时不能区分所有同额交易。
- `createdAt` 是录入时间。当前部署使用 Asia/Shanghai，业务日期与时间不含 UTC 偏移。
- 预算事件是设置变化的事实来源；交易类型仅 `expense` 和 `refund`。当前文本收单按既有用户规则把普通进账记为 `refund`；它不自动证明是某项固定退款，固定用途必须自行明确分摊。
- 通知、短信、Wallet 等输入由快捷指令提供；PWA 自己不能直接监听其他 App 的交易通知。
