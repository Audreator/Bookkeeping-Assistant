# 指南：微信 / 支付宝 CSV 账单补录

在支付 App 内使用当前提供的个人对账导出功能，把账单发到自己的邮箱并下载。微信通常从钱包账单的常见问题/下载账单入口进入，支付宝通常从账单的交易流水证明/导出入口进入；菜单随版本变化，以 App 实际显示为准。

用邮件或支付 App 提供的密码在自己的设备解压，得到 `.csv`；当前不直接读取加密 ZIP、PDF 或招行独有格式。记账本 → 设置 → 数据 → 账单对账导入 → 选择 CSV → 检查预览 → 导入。

## 当前解析规则

- 自动识别微信/支付宝相近的表头，支持 UTF-8 与 GBK 解码。
- 保留交易日期与秒级时间；只有分钟时补 `:00`，没有时间留空。
- 普通收入/转入不作为退款。显式退款成功或退款类型的成功行才录退款。
- 失败、关闭、取消、处理中、未支付等状态不导入。原支付支出行后来显示「已全额退款/已部分退款」时，仍保留原支出金额，退款需独立退款明细；不会把原订单总额当本次退款。
- 金额正数元且最多两位小数，无效日期、时间和金额跳过。
- 导入保存 `source: import`，页面来源标记「自动」；按历史完全相同商户的最近分类建议归类。

## 去重与核对

比较金额、收支类型、相似商户。两边都有时间时要求日期和时间一致；一边缺时间时使用日期相差不超过 3 天的兼容窗口。每条已有交易最多匹配一条账单行，减少同額多笔被一条记录全部吞掉的情况。

此规则是辅助核对，缺时间、相似商户或跨来源模板可能造成误匹配/漏匹配。不能保证自动对账准确覆盖所有部分退款、聚合支付、代付、花呗还款、外币及新版格式。检查预览中的新记录与跳过数量，导入前后抽查原支付和退款；发现问题保留匿名 CSV 行并补解析测试。

预算、导入比对与备份通过分页获取全量交易，超过默认接口页大小的旧记录不会仅因分页上限被遗漏。导入预览前重新读取最新完整账本；读取失败时不生成预览、不写入。CSV 逐笔请求，网络中途失败时保留剩余行和稳定请求 ID，恢复网络后在同一弹窗重试。写入期间不能关闭；成功行已移除。若重新选择文件，仍须检查预览的去重结果。
