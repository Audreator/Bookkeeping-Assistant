# 指南：iPhone 快捷指令与支付自动记账

从手工测试开始，再接截图或通知自动化。动作名称和自动化入口会随系统版本变化，以手机上实际显示的内容为准。本文的文本、金额、卡尾号和事件 ID 均为合成示例，不对应个人账目；服务器地址、登录信息及令牌请填写自己的配置。

## 先准备手机与服务器

1. 按 [手机运行指南](local-preview.md) 启动服务器，手机 Safari 能打开应用并登录。
2. 在服务器项目根目录的私有 `.env` 设置 `INGEST_TOKEN`，重启服务。把该值复制到自己的快捷指令；不要公开分享含令牌的快捷指令、截图或导出文件。
3. 记下自己实际可访问的服务地址。局域网写为 `http://<服务器IPv4>:8787`，HTTPS 部署写为自己的域名；下文的 `<服务器IPv4>` 必须替换，不能直接照抄。
4. 快捷指令收单用独立令牌，不用网页登录密码或登录 JWT。手机需要能连到服务器，电脑休眠/关机和网络断开时都不能新增记录。

完整参数见 [收单 API](ingest-api.md)。推荐 JSON 请求体，令牌放请求头，交易原文放请求体。

## 第一步：手工跑通接口

这会在自己的账本写入合成测试交易，不会真的付款。完成后可在账本删除测试支出与退款。

1. 打开「快捷指令」→ 新建，命名「记账接口测试」。
2. 添加「文本」动作，在里面填以下内容，每个字段单独一行：

   ```text
   支付成功
   支付金额：¥2.46
   商户：示例商店
   ```

3. 添加「URL」动作，填 `http://<服务器IPv4>:8787/api/ingest/ocr`，并替换地址；HTTPS 部署则填自己的 HTTPS 地址及同一路径。
4. 添加「获取 URL 内容」。它的输入选择第 3 步的 URL 魔法变量；展开设置，按表填写：

   | 设置项 | 内容 |
   |---|---|
   | 方法 | `POST` |
   | 标头名称 | `x-ingest-token` |
   | 标头值 | 自己的 `INGEST_TOKEN`，不包含键名或额外引号 |
   | 请求体 | `JSON` |
   | 第一个字段名称 | `text`，类型选择「文本」 |
   | 第一个字段值 | 点击值输入框 → 选择变量 → 第 2 步「文本」动作的输出 |
   | 第二个字段名称 | `eventId`，类型选择「文本」 |
   | 第二个字段值 | 合成测试标识，例如 `guide-demo-expense-001` |

   不要在 JSON 字段值中手动输入 `{"text":...}`，也不要选择「此操作」或整个 URL 动作作为 `text`。字段编码由「获取 URL 内容」完成。
5. 添加「显示结果」，输入选择「获取 URL 内容」的输出。首次运行时按提示允许访问自己的服务器。
6. 点运行。成功结果有 `message`、`transaction` 和 `duplicate: false`；打开账本，核对示例商店、支出类型和金额。没有消息时间的这个示例保存服务器接收日期和秒级时间。
7. 原样再次运行：应为 `duplicate: true`，返回原记录，不新增第二笔；首次保存的时间也保持不变。若之前用过相同测试 ID，第一次就可能返回重复，先核对已有记录。
8. 将「文本」改为下面内容，把 `eventId` 改为 `guide-demo-refund-001`，再运行：

   ```text
   退款成功
   退款金额：¥2.46
   商户：示例商店
   ```

   应新增独立退款，原支出仍保留。退款事件不能沿用原支付的 `eventId`。
9. 再以新的测试 ID 把状态改为「退款处理中」或「支付失败」。应返回未识别交易（`422`），账本不新增。普通「收入/收款/转入/账户入账」现在按退款入账，工资、利息等纯收入也会记成退款，需要自行核对。

界面弹出结果不等于入账成功，要看返回的内容并核对账本。网络错误、`400` 或 `422` 要保留为失败结果，不能统一显示「成功」。

## 第二步：操作按钮截图与分享历史截图

建议复制已跑通的快捷指令，命名「记账识别」，保留 URL、POST、请求头和显示结果，替换原先的测试输入。删除合成测试的固定 `eventId`；日常只有能取得稳定来源交易号或保存首次生成的事件标识时再添加它。

### 分支 A：当前支付/退款详情

1. 将「文本」动作替换为「截屏」。
2. 紧接着添加「从图像中提取文本」，输入选「截屏」的输出。
3. 在「获取 URL 内容」的 JSON 字段 `text` 中，删除旧魔法变量，重新选择 OCR 动作输出的文字；字段类型仍是「文本」。
4. 请求体先只保留 `text`，省略 `date` 和 `time`，让服务器优先提取截图的原交易日期和时间。
5. 打开付款成功详情或退款到账详情，使用操作按钮、轻点背面、控制中心或其他入口运行。不要在快捷指令编辑页点运行来验证付款截图，否则截到的是编辑页。
6. 有操作按钮的机型：设置 → 操作按钮 → 快捷指令 → 选「记账识别」。其他机型可从设置 → 辅助功能 → 触控 → 轻点背面选择快捷指令。入口取决于设备能力。[Apple 操作按钮说明](https://support.apple.com/guide/shortcuts/run-shortcuts-with-the-action-button-apdfea15680b/ios)。

详情里同时显示余额、优惠和原订单金额时，核对返回的金额是否为本次实付/退款。只有「退款申请」「预计到账」或正号，不是完成退款的证据。

### 分支 B：相册分享历史截图

分享原截图比对着相册再次截屏更容易保留完整详情。

1. 复制「记账识别」，命名「历史截图记账」。
2. 在快捷指令详情中启用「在共享表单中显示」，输入类型只选择「图像」。[Apple 分享入口说明](https://support.apple.com/guide/shortcuts/run-a-shortcut-from-another-app-apd163eb9f95/ios)。
3. 删除「截屏」动作，把「从图像中提取文本」的输入改为「快捷指令输入」。
4. 保留 OCR 输出 → JSON `text` → POST → 显示结果；仍先省略 `date/time`。
5. 相册打开一张历史交易截图 → 分享 → 选择「历史截图记账」。每次只分享一张单笔详情；多笔通知或多张图不要一次混合提交。
6. 原文没有年份或日期时，手动补充已确认的 `date`。历史原文没有时间但不希望使用接收时间时，改在 App 内手工记账并留空时间。

也可合成一个快捷指令：开头用「如果快捷指令输入有任何值」，有输入时对输入图像 OCR，无输入时先截屏再 OCR；两条分支分别设同一个文字变量，再由统一 POST 动作读取。先分别跑通两个分支再合并。

## 第三步：通知自动化

支持通知触发器的系统可以按 App 和通知内容运行快捷指令。Apple 的 [iOS 27 事件触发器指南](https://support.apple.com/guide/shortcuts/apd932ff833f/10.0/ios/27) 列出了 Notification，可按 Message、Subtitle、Title 筛选；同页也列出截屏保存触发器。这是版本能力说明，不代表所有手机或支付 App 都提供相同输入。

1. 在手机实际的自动化入口寻找「通知」。新版本可能从快捷指令编辑 → 自动化进入；其他版本可能在「自动化」页建立个人自动化。不存在该触发器时，先用 OCR、短信/邮件或手工参数方案。
2. 选择需要处理的银行/支付 App，先只启用「显示结果」，输入选自动化提供的「通知」变量，检查一笔通知到底包含哪些字段。
3. 点击蓝色「通知」变量，查看能否选「信息」「正文」「消息」或类似文字属性；优先选择包含金额和最终状态的正文文字，不能只发通知标题。
4. 若得到的是文字：直接用它做 JSON `text` 的值，字段类型「文本」。
5. 若得到的是通知对象：优先加「从输入中获取文本」，检查输出是否真的包含正文，再把输出传给 `text`。如果仅显示对象名称、App 名称或空白，转换没有得到交易原文，应重新选正文属性。
6. 最终动作顺序为「通知正文/提取文字」→「获取 URL 内容」→「显示结果」；POST 配置与第一步相同：`x-ingest-token` 标头，JSON 键 `text`，值选择正文文字输出。
7. 为支出和退款分别设置最终状态筛选。银行「账户出账/已扣款」是支出证据；「收款/转入/入账」会记为退款，但工资、利息等纯收入也会落到退款里，需要自行核对。
8. 用实际支付与退款分别核对结果，再验证通知重复、延迟、锁屏和网络不可达。系统提供免确认/锁定时运行设置时按需启用；Apple 指南同时提示个别动作可能另需权限，不能假设通知触发器在所有锁屏情况下都可完整执行。[Apple 自动化设置](https://support.apple.com/guide/shortcuts/add-automations-apdfbdbd7123/10.0/ios/27)。

如需同时保留标题和正文，可添加「文本」动作，把两个文字属性用换行连接，再把这个「文本」动作输出送入 `text`。

### 通知对象兼容与 400 诊断

服务器也兼容已序列化的通知对象。例如：

```json
{
  "text": {
    "title": "银行动账通知",
    "body": "支付成功\n支付金额：¥2.46"
  }
}
```

常见正文键有 `body`、`message`、`text`、`content`、`正文`、`信息`、`消息`、`内容`；标题与副标题也可合并。该兼容不意味着任意系统对象都能转成 JSON；多笔数组、未知结构或同组字段内容冲突会拒绝。新手先使用「正文文字 → text 文本字段」最容易排查。

若返回 `400`，查看 `invalidFields` 与 `inputShape`：

- `text` 显示字符串且长度大于零：检查错误字段是否为日期/时间格式。
- `text` 显示对象且只有未知字段：重新取正文文字，或按兼容的字段构造对象。
- `text` 为数组、多笔内容、数字或空值：选单条通知的文字属性。
- `inputShape` 只描述字段结构、类型与长度，不含正文值；分享诊断前仍检查字段名是否包含个人信息。不要附令牌、原始通知、账户信息或完整服务地址。

### 已覆盖的匿名银行模板

这些模板已进入解析与收单回归测试。下列金额、卡尾号及日期时间为替换后的演示值，只说明文案形状；不代表银行所有版本或所有交易都已验证。

| 合成通知示例 | 预期 |
|---|---|
| `动账通知：您尾号1234的账户出账 网联支出2.46元` | 支出；无明确商户时留空，缺消息时间时保存接收时刻 |
| `您账户1234于01月02日09:08发生快捷支付扣款，人民币2.46` | 支出；月日按引用日期推断最近相邻年份，分钟补零 |
| `账户入账人民币2.46元` / `网联 入账收入2.46元` | 记为一笔退款（进账）；无消息时间时保存接收时刻 |
| `快捷支付扣款失败` / `账户出账处理中` / `预计账户出账` | 不入账 |
| `退款成功，退款金额人民币2.46元` | 明确退款；按本次退款金额识别 |
| `发生一笔38.00元的消费` / `扣费成功 28.00元` | 支出；扣费、付费、花费、取现、转出、缴费、还款等近义词同样识别 |
| `退货成功` / `退费成功` / `交易已撤销` / `已原路退回` | 退款；退回、退还、退货、退单、退费、冲正、返款、返还、撤销等近义词同样识别 |
| `支付成功后可返还20.00元` / `最高返还¥50.00` | 不入账；条件与营销文案不算退款 |

只有银行名称或「财付通/微信支付/支付宝」等支付通道信息时，不猜真实商家。来源只有月日的通知适合实时接收；历史内容跨年或长期延迟时，应显式填写已经确认的完整日期。

项目曾验证手机发送正文字符串能完成收单；公开记录只保留这一匿名结论。锁屏、每种支付平台的退款和所有通知字段仍需在实际设备分别验证。

## 日期、时间与重试规则

| 参数 | 建议 |
|---|---|
| `date` | 已确认交易日期，`YYYY-MM-DD` |
| `time` | 已确认交易时间，`HH:mm:ss`；也接受分钟 `HH:mm` |
| `eventId` | 来源交易号或同一事件首次生成后保存的标识，1–128 字 |

日期优先级是显式 `date` → 原文交易日期 → 接口接收日期；时间是显式 `time` → 原文交易时间 → 接口接收秒级时间。来源时间只有分钟会补 `:00`，这不代表原文提供了秒。历史记录、CSV、邮件与手工记录仍可能保留未知时间。

OCR 和通知默认省略 `date/time` 可保留原文优先级；不要无条件把「当前日期」填进字段，否则会覆盖历史消息里的交易时间。接收时间是网络到达服务器的时间，不等同于实际支付时间。手工实时记账确需提供当前时间时，「格式化日期」用 `yyyy-MM-dd` 和 `HH:mm:ss`，其中 `MM` 是月份、`mm` 是分钟。

有交易号时用来源名称和交易号生成 `eventId`；没有交易号时可以首次记录前生成 UUID 并保存。同一事件每次重试保留原 ID、原类型、原金额及原消息参数；支付与退款用不同 ID。不要重试时新建 UUID，或为了绕过去重伪造当前交易时间。

无来源时间的接收秒数不参与去重，原事件重试返回第一次记录。稳定 `eventId` 还能保护跨午夜重试。没有 ID、真实时间或商户等区别信息时，实际多笔同额交易仍可能无法区分；不同日期的无 ID 请求也可能成为新记录。超时先查账本，重试沿用原事件 ID。

## 结构化快捷指令与其他通道

已由自己确认支出/退款及准确金额时，可用 `POST /api/ingest/transaction`：请求头相同，JSON 字段 `type` 填 `expense` 或 `refund`，`amount` 填正数元（最多两位小数），按需加 `date`、`time`、`merchant`、`note`、`eventId`。该接口不判断原支付是否成功，类型完全由调用方指定；无法确认时不要猜，先核对账单。

短信/邮件自动化按设备支持的发件人与关键词条件触发，先确认输入能取原文，再 POST。Wallet 的 Transaction 触发器文档明确选定卡被轻触时触发，未保证最终金额、退款或扫码支付覆盖；字段不足时只用于提醒自己补录。[Apple 通信触发器](https://support.apple.com/guide/shortcuts/apdd711f9dff/10.0/ios/27)，[Wallet 触发器](https://support.apple.com/guide/shortcuts/apd65c67538a/10.0/ios/27)。

服务器 IMAP 与月度 CSV 是异步补录通道，见 [QQ IMAP](qq-imap.md) 和 [账单导出](bill-export.md)。各通道不保证跨来源自动对账。

## 排查与验收

| 现象 | 处理 |
|---|---|
| 网络无法连接 | Safari 是否可打开同一地址；服务器是否运行、同局域网、防火墙是否允许 8787 |
| `401` | 请求头令牌与服务器配置一致；没有多复制键名、空格或引号；服务器已重启 |
| `503` | 服务器是否配置收单令牌与可用归属账号 |
| `400` | 查 `invalidFields/inputShape`、文字类型、日期与时间格式 |
| `422` | 原文无明确完成状态或唯一金额，改用详情/手工确认 |
| `409` | 同一事件 ID 被用于不同交易，核对源记录 |
| `duplicate: true` | 已有同一事件，查看返回交易；不要生成新 ID 盲目重复 |
| 入账后页面未刷新 | 刷新账本并核对用户归属，外部写入可能等下一次轮询 |
| 截图是空白 | 来源 App 可能限制截屏，使用可见详情、分享文字或手工补录 |

- [ ] 支出、独立退款、重复重试与失败状态均符合预期。
- [ ] 消息原日期/时间优先，历史截图不被当前参数覆盖。
- [ ] 锁屏、延迟、多笔同金额与每个实际来源分别验证。
- [ ] 网络断开明确失败，恢复后用原事件 ID 重试；当前没有离线发送队列。
- [ ] 对外分享快捷指令前移除令牌、地址、个人变量及通知原文。

服务日志只用于诊断，不把完整通知或密钥复制到公开 issue。若使用截屏保存触发器，应读取刚保存的图像，不能再执行「截屏」产生递归。
