# 指南：QQ 邮箱 IMAP 与银行邮件

服务器已有可选 IMAP 轮询；没有配置时不运行。需要银行真实发送单笔支出/退款邮件，并先校准模板，不能仅凭开通月度电子账单就认为每笔交易可自动入账。

## 配置与校准

1. 在 QQ 邮箱的账号设置查看并开启当前提供的 IMAP 服务，按官方页面完成验证，生成邮箱授权码。界面路径可能随邮箱版本变化。
2. 邮箱地址与授权码直接填写电脑 `.env`，无需放进聊天、仓库或公开截图。授权码不等同于 App 登录密码。
3. 先保留 `AUTO_EMAIL_USER` 为空，执行 `npm run email:dry`：扫描最近 7 天匹配发件地址的邮件，打印解析结果，不写数据库。核对支出、退款、普通收入与失败/处理中内容。
4. 用匿名真实消费和退款样本补充解析测试。结果准确后填入入账用户 ID，重启服务，抽查首次入账结果。
5. 常规轮询扫描最近 3 天收件箱，默认每 60 秒一次；停机超过扫描窗口时，需要人工补录或专项扩大扫描范围。

```dotenv
IMAP_HOST=imap.qq.com
IMAP_PORT=993
IMAP_USER=自己的邮箱地址
IMAP_PASS=自己的邮箱授权码
BANK_SENDER_FILTER=cmbchina.com
AUTO_EMAIL_USER=自己的入账用户ID
EMAIL_POLL_SECONDS=60
```

配置中的中文说明必须换成自己的真实值；`AUTO_EMAIL_USER` 填数字。dry 输出包含商户、主题、卡尾号和正文摘要，分享前去除隐私信息。

## 入账与诊断

- 来源为 `bank-email`，App 显示「自动」；解析到交易日期/时间时保留，未提供交易时间不使用收信时间冒充。
- `email_receipts` 保存 Message-ID、状态、交易关联与原文审计；相同用户和 Message-ID 的交易/收据在数据库事务内防重，缺失 Message-ID 时用邮件内容摘要生成稳定标识。
- 常规启动日志显示邮件轮询启用；命中后打印扫描/结果。解析失败保留收据用于调查，不保证每笔都自动写入。
- 邮件去重不自动与 OCR 或 CSV 对账；同一银行卡交易从多个来源出现时需核对。

## 当前边界

`BANK_SENDER_FILTER` 配置完整邮箱时只允许该邮箱，配置域名时允许该域及其真正子域，拒绝仅含银行域名字符串的仿冒地址。尚无 DKIM/DMARC 签名验证，地址匹配不能证明邮件真实来自银行。解析复用严格完成状态与金额规则；银行账户类型、提醒门槛、通知延迟和字段变化仍需真实验证。

授权码只存在自己 `.env`，可在邮箱撤销。邮件正文和收据会落入自己的 MySQL，备份也包含它们。当前没有 Web Push 通知或 Cloudflare 邮件 Worker。
