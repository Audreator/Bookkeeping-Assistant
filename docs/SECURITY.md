# 安全与隐私

## 当前实现

- 自托管服务器和 MySQL 存储。开发 Compose 的 MySQL 监听 `127.0.0.1:3306`，生产 Compose 不发布数据库端口。
- 当前固定个人账号，生产注册关闭。登录用 bcrypt（cost 10）保存哈希；前端先 SHA-256 预哈希，预哈希值仍等价于登录凭据，HTTP 明文不因预哈希变成安全连接。
- JWT HS256，30 天有效，请求中签发超过 7 天时用响应头 `x-jizhang-token` 换发。连续错误 5 次冷却 5 分钟；唯一会话使新设备登录后旧设备失效，登出吊销会话。
- 业务路由强制 `user_id` 过滤并核对分类/关联交易归属。前端令牌存在 localStorage；备份可用 AES-GCM 与 PBKDF2 加密。
- 收单 API 使用独立静态 `INGEST_TOKEN`，不使用浏览器登录 JWT。令牌持有者能向配置用户写入交易，应作为密码保管。更换令牌并重启服务即可使原令牌失效。
- 收单日志不应输出令牌和完整 OCR/通知原文；邮件收据表会保存邮件正文，数据库级备份含这部分隐私数据。

## 收单保护与边界

日期、时间、交易类型及金额格式校验，文本解析拒绝未明确成功的支付/退款。稳定事件 ID 与数据库唯一键保护同一收单通道的重试；它们不会认证银行原始消息真伪，也不会自动匹配所有跨来源账单。

快捷指令令牌只放在私有 `.env` 和自己的快捷指令；不要公开分享带令牌的快捷指令，或把令牌放进查询参数。若凭据曾被公开，先更换配置并同步自己的快捷指令；仅删除当前文件不能撤销已经泄露的凭据。

公开源码只保留合成示例与匿名验证结论。不得提交真实用户名、邮箱、账户/卡号、通知正文、服务地址、个人目录、设备标识、真实调用金额与时刻、日志、数据库备份或带个人变量的快捷指令。通知 `inputShape` 仅描述结构、类型和长度，但字段名也应在公开反馈前人工检查。版本能力说明引用 Apple 官方文档，不记录个人设备的版本组合。

IMAP 本轮补充发件地址完整匹配：配置邮箱时只允许该邮箱，配置域名时允许该域及真正子域，拒绝仿冒包含字符串。仍没有 DKIM/DMARC 签名验证，地址匹配不能证明邮件真实来自银行。解析复用严格支付/退款规则，覆盖已写测试的模板；启用前用真实样本校准。本轮通过数据库事务将 Message-ID 收据与交易关联，并增加并发测试；它不等同于跨来源统一对账。

## 部署与备份

局域网 HTTP 会明文传输登录与收单凭据；日常在自己可信网络使用，公网部署启用 HTTPS。云端使用强 JWT 密钥、随机收单令牌和独立数据库密码，不向公网开放数据库。当前 CORS 设置宽松，不应把跨域限制作为鉴权保护。

`.env` 不进版本库；`.env.example` / `.env.prod.example` 只保留示例。登录密码在启动时由 `DEFAULT_PASSWORD` 校正，改密码后重启服务。备份文件默认包含明文数据，按实际需要使用 App 加密导出并保管口令。

服务器持有者可以看到明文交易、邮件收据与日志。当前未实现数据库静态加密、App PIN/Passkey、Web Push 或 Cloudflare 密文中转，不能宣称已有这些保护。
